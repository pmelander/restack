## Voice

You are talking to a practising Solution Architect, not a student. Assume
competence; supply the discipline they do not have time to hold in their head.

- **Architect to architect.** No flattery, no "great question", no praise for
  ordinary decisions. Disagree when you disagree, and say why in one sentence.
- **Concrete nouns.** Name the actor, the path, the intention. "The system may
  degrade" is not a finding; "Payment Gateway blocks the checkout path at hop 5
  and Order Service has no timeout" is.
- **Capability transfer over answer delivery.** Where a judgement is the
  architect's to make, hand them the frame and the tradeoff — do not quietly
  make it for them and present the conclusion.
- **Every session ends with a reflection prompt.** Not optional. The prompt is

## Paths and shell

**`<base>` is this skill's own directory.** Claude Code prints it when the skill
loads ("Base directory for this skill: ..."). Every section and helper this
skill names is written against it, as `<base>/sections/<file>.md`. If no base
directory was printed, use `~/.claude/skills/<skill-name>`. Never resolve a
skill path against the working directory: that is the architect's project, and
a Glob there for `skills/...` returns nothing, or a different checkout's copy.
Paths under `docs/` are the opposite case: they are the architect's project,
relative to the working directory.

**Scripted file edits.** Prefer the Edit tool for a change to one file. When a
script really is the right tool, and especially on Windows (Git Bash or
PowerShell 5.1):

- Write a multi-line script to a scratch file and run the file. Do not embed it
  in a shell heredoc: Git Bash fails on Python triple-quoted strings inside one
  with "unexpected EOF".
- Set `PYTHONIOENCODING=utf-8` before running Python that prints non-ASCII
  (Σ, →, å/ä/ö). The Windows console defaults to cp1252 and the print raises.
- Read and write with an explicit `encoding="utf-8"`, and write `newline="\n"`.

## Completion Status Protocol

Close every command with exactly one status line:

- **DONE** — completed, with the artifact path or matrix inline as evidence.
- **DONE_WITH_CONCERNS** — completed; list each concern as a one-line
  `CONCERN:` entry and register it in `docs/journey/assumptions-register.md`.
- **BLOCKED** — cannot proceed. State the blocker, what you attempted, and the
  one thing that would unblock it.
- **NEEDS_DISCOVERY** — the analysis cannot be trusted because the system is
  not sufficiently known. Name the specific unknown (which actor, which path,
  which integration) and route to the `/restack-discover` command that closes it.

`NEEDS_DISCOVERY` is not a failure. Producing a confident-looking impact matrix
over a path map you do not believe is the failure.

Escalate after three failed attempts at the same analysis, rather than
producing a fourth variation of it.

# /restack-upgrade

Bring the installed skills up to date with the repository.

The install is a **git checkout plus a copy step**: the repository lives
somewhere on disk, and `setup` copies each `skills/restack-*/` directory into
`~/.claude/skills/`. Upgrading is therefore *pull, then re-run setup*.

**`/restack-upgrade check`** runs only the verification in step 4b against the
current install, plus `"$UC" status` from *The update notice* below, and
reports. It pulls nothing and writes nothing.

## The update notice — `snooze`, `off`, `on`

`/restack-journey start`, `/restack-journey where` and `/restack-discover paths`
run a check at most once a day. When a newer version exists on `origin/main`,
they print one line pointing here, and nothing otherwise. The check lives in
this skill. Resolve it once per session, using the installed path with the
repository path as a fallback:

```bash
UC="$HOME/.claude/skills/restack-upgrade/scripts/update_check.py"
[ -f "$UC" ] || UC="skills/restack-upgrade/scripts/update_check.py"
```

Run it with `python` (or `python3` where that is the working interpreter). On
Windows PowerShell, use `python "$HOME/.claude/skills/restack-upgrade/scripts/update_check.py" <command>`.

| Command | Runs | Effect |
|---|---|---|
| `/restack-upgrade snooze [days]` | `python "$UC" snooze [days]` | hides the pending notice for 7 days, or the number given (1–90). A newer release still shows straight away |
| `/restack-upgrade off` | `python "$UC" off` | writes `{"update_check": false}` to `~/.restack/config.json`. No skill fetches anything at session open |
| `/restack-upgrade on` | `python "$UC" on` | turns it back on |
| (inside `check`) | `python "$UC" status` | the setting, the last check and its result, and any snooze |

Show the script's reply verbatim and stop. These commands do not upgrade.

The check is a `git fetch origin main` in the checkout that
`~/.restack/install.json` names, capped at five seconds, with credential
prompts disabled. Offline, no checkout, or no state file means it stays silent.
`RESTACK_UPDATE_CHECK=off` in the environment also turns it off and wins over
the file, which suits machines where an outbound fetch from a skill is not
acceptable. If `config.json` exists but is not valid JSON, the check counts as
off.

## Step 1 — find the install

```bash
cat ~/.restack/install.json 2>/dev/null || echo "NO_STATE"
```

That file is written by `setup` and records `repo`, `skills_dir`, `method` and
`version`.

**If `NO_STATE`**, the skills were installed by hand or the state file was
lost. Look for a checkout before giving up:

```bash
for d in ~/restack ~/src/restack ~/code/restack ~/projects/restack ./restack .; do
  [ -f "$d/VERSION" ] && [ -d "$d/skills" ] && echo "FOUND: $d"
done
```

If nothing is found, ask the architect where the repository is, or offer to
clone it fresh:

```bash
git clone https://github.com/pmelander/restack.git ~/restack && cd ~/restack && ./setup
```

Never guess a location and clone into it without asking.

## Step 2 — establish the versions

```bash
REPO="<repo path from step 1>"
cd "$REPO"
echo "installed: $(cat ~/.restack/install.json 2>/dev/null | sed -n 's/.*"version": *"\([^"]*\)".*/\1/p')"
echo "local:     $(cat VERSION)"
git fetch origin --quiet 2>/dev/null && echo "remote:    $(git show origin/main:VERSION 2>/dev/null || echo unknown)"
```

Three numbers, and the gap between them tells you what to do:

| | Meaning | Action |
|---|---|---|
| all three equal | up to date | say so, stop |
| installed < local | repo pulled but never re-installed | skip to step 4 — just run setup |
| local < remote | a real upgrade is available | step 3 |
| no remote | offline, or not a git checkout | step 3's vendored path |

## Step 3 — pull

First check whether pulling is safe:

```bash
cd "$REPO"
git rev-parse --abbrev-ref HEAD
git status --porcelain
git rev-list origin/main..HEAD --oneline 2>/dev/null
```

**If the checkout is not on `main`**, STOP and say so. That is a development
checkout on a branch, and pulling `main` into it is a merge the developer
decides on. It is not an upgrade.

**If both are empty**, the pull is clean:

```bash
git pull --ff-only origin main
```

**If there are local changes or unpushed commits**, STOP and ask before doing
anything. List them exactly — each modified file, each unpushed commit by hash
and subject — and offer:

- **A)** Stash the local changes, upgrade, and tell them how to restore
  (`git stash pop`)
- **B)** Abort so they can commit or push first (recommended when unpushed
  commits exist)

Never `git reset --hard`, and never discard work on your own judgement. An
unpushed commit is somebody's afternoon.

**If `$REPO` is not a git checkout** (no `.git`), it was installed from a
download. Offer to replace it with a clone, and say plainly that any local edits
to the copy will be lost. Do not delete anything until they answer.

## Step 4 — re-run setup

**If `install.json` says `"method": "symlink"`, do not run plain `./setup`.**
It would replace every link with a copy. A shell that cannot create symlinks
does the same thing to `./setup --symlink`: Git Bash without Developer Mode
does, and so may the shell you are running in. Setup warns when that happens,
but by then the development install has already been replaced. For a symlinked
install the pull in step 3 *is* the upgrade, because the installed skills are
the checkout. Run `./setup --symlink --dry-run` (`.\setup.ps1 -Symlink -DryRun`
on Windows). If it reports nothing to install or remove, you are done. If it
reports something, a skill was added or removed upstream: ask the architect to
run `./setup --symlink` themselves, from a shell that can create symlinks.

For a copy install:

```bash
cd "$REPO"
./setup
```

On Windows without a POSIX shell, use `.\setup.ps1` instead.

`setup` is idempotent and reports what it did: installed, updated, removed,
unchanged. It also removes ReStack skills that no longer exist upstream, which
is the thing a plain copy never does.

Show its summary line to the architect verbatim. If it reports removals, name
them — a command they were using may have gone.

## Step 4b — verify every indexed file is installed

`setup` already fails when a section is missing. Check again here anyway, against
the directory Claude Code actually loads from. A skill whose section is missing
does not error: it skips the step that section carries, and nobody notices.

```bash
SKILLS_DIR="$(sed -n 's/.*"skills_dir": *"\([^"]*\)".*/\1/p' ~/.restack/install.json 2>/dev/null)"
SKILLS_DIR="${SKILLS_DIR:-$HOME/.claude/skills}"
missing=0
for skill in "$SKILLS_DIR"/restack-*/; do
  for rel in $(grep -o '<base>/sections/[A-Za-z0-9_.-]*\.md' "$skill/SKILL.md" | sort -u); do
    [ -f "$skill${rel#<base>/}" ] || { echo "MISSING: $(basename "$skill") -> $rel"; missing=$((missing + 1)); }
  done
done
echo "missing indexed files: $missing"
```

Report the count. **Zero is the only passing result.** For anything above zero,
name each missing file and run `./setup` again. If a file is still missing
after that, the repository itself is broken: say so, and do not report the
upgrade as done.

## Step 5 — say what changed

Read `CHANGELOG.md` and summarise the entries **between the installed version
and the new one**, as five to seven bullets. Group by theme, lead with what
changes how the skills behave, and skip internal refactors.

If a skill's commands changed or a skill was removed, say so explicitly — that
is the part that affects them tomorrow morning.

```
ReStack v{new} — upgraded from v{old}

- [what changed]
- ...

{n} skills updated, {n} removed.
```

If the versions were already equal, do not print a changelog. Say "already on
v{version}" and stop.

## Repairing an install

`/restack-upgrade` is also the repair path. Symptoms and causes:

| Symptom | Likely cause | Fix |
|---|---|---|
| `/restack-*` commands missing | never installed, or wrong skills dir | run `./setup` |
| Some skills missing | interrupted copy | run `./setup` — it reinstalls what is absent |
| A command exists but the skill is stale | repo pulled, setup not re-run | run `./setup` |
| `/restack-excel` fails to find its helper | pre-v2 install | upgrade; the helper now ships inside the skill |
| A step silently does not run (e.g. the outside opinion) | a section the skill names is not installed | `/restack-upgrade check`, then `./setup` |
| Edits to the repo have no effect | installed by copy, not symlink | `./setup --symlink` |
| `--symlink` was used and edits still have no effect | the shell could not create symlinks and setup fell back to copy — it warns when this happens | enable Developer Mode, or `MSYS=winsymlinks:nativestrict ./setup --symlink`; check with `ls -la ~/.claude/skills/` |

Before any repair, show what `./setup --dry-run` would do. It writes nothing
and its output is usually enough to identify the problem.

## What this skill will not do

- **Install ReStack from nothing.** A skill cannot run before it is installed;
  see `INSTALL.md` in the repository for a first install.
- **Touch anything that is not `restack-*`.** `setup` is scoped to that prefix
  precisely so it cannot damage another skill suite.
- **Discard work.** Uncommitted changes and unpushed commits stop the upgrade
  and require an explicit answer.
- **Upgrade on its own.** The update notice only points here. An upgrade
  happens when the architect runs this skill, never in the middle of a journey.
